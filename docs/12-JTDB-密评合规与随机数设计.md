## 1. 目标与范围

本文解决规划文档 P1-5：密评合规前置与随机数来源设计。

- 支撑**商用密码应用安全性评估（密评，GB/T 39786-2021）**三级系统要求，为等保四级场景预留升级路径；
- 密码模块按 **GM/T 0028 二级**起步定级（决策记录 #6）；
- 冻结随机数方案，作为 `JtEncryptedObject` 对象格式冻结的**前置条件**（实现方案 §4.3）；
- 不含：TLCP 协议细节（实现方案 §5.4 及互操作专项）、KMS 密钥层次与轮换协议（ADR-013/014）、MLS 标签模型（ADR-011）。

> 标准编号约定：本文引用的标准编号以密码专项评审的核对结果为准（沿用 TLCP"GB/T 38636-2020"的统一核对做法）。

## 2. 密评指标映射

GB/T 39786 技术要求分四个层面，每个层面从真实性、机密性、完整性、不可否认性四性检查。JTDB 的映射：

| 密评层面 | 四性要点 | JTDB 落点 | 证据来源 |
|---|---|---|---|
| 物理和环境安全 | TCM/密码卡等硬件密码资源在机房侧的部署与检测 | 属于部署环境责任；jt-attest 负责探测 TCM/HSM 并纳入证明链（实现方案 §6.4） | 硬件清单 + attest 度量记录 |
| 网络和通信安全 | 通信真实性（TLCP 双证书）、机密性（SM4）、完整性（SM3 MAC/AEAD） | jt-gateway 对外 TLCP（GB/T 38636-2020）；三平面间 mTLS/TLCP + 请求签名（实现方案 §2.2） | 配置基线 + 握手审计事件 |
| 设备和计算安全 | 管理身份真实性（SM2 证书/SM3 口令/UKey）、管理通道保护、登录审计 | jt-identity 组件身份与人身份（见《身份与节点引导设计》）；三权分立（ADR-012） | 认证审计 + 证书台账 |
| 应用和数据安全 | 存储机密性（SM4 全生命周期）、数据完整性（SM3/AEAD Tag）、不可否认性（SM2 签名锚点 + TSA） | WAL/Layer/快照/备份加密（ADR-013）；审计哈希链 + TSA 锚定（实现方案 §7.3） | 密钥台账 + 审计链校验报告 |

管理层面的制度、人员、建设、应急处置要求由交付工程工作域的《密评实施手册》承接，不在本文范围。

## 3. 密码模块边界与定级

### 3.1 模块边界

```text
JTDB 密码模块边界
├── jt-kms 密码子模块（RK/KEK/DEK 封装、DRBG 调度、密钥零化）
└── jt-crypto-api 及其后端（tongsuo-backend / pure-rust-backend，实现方案 §5.4）
```

Pageserver/Safekeeper/Compute 通过 jt-crypto-api 使用密码能力，自身不实现密码原语。

### 3.2 二级要求落点（GM/T 0028）

| 二级要求 | JTDB 落点 |
|---|---|
| 上电自测试 / 条件自测试 | jt-crypto-api 启动自检（SM4 加解密回环、SM2 签名回环、DRBG 健康检测）；失败则组件拒绝服务 |
| 运行状态管理 | 模块状态机（自检/正常/错误/降级），状态进审计 |
| 访问控制 | KMS 租约 + attestation 绑定（ADR-013）；组件身份证书 |
| 事件日志 | 密码操作事件进审计平面（密钥生成/释放/轮换/销毁） |
| 密钥零化 | Retire 阶段 DEK 销毁 + 内存零化；加密擦除语义（ADR-013） |

### 3.3 合规主路径（2026-09-03 依外部审计细化）

外部核实（2026-09-02）：铜锁 Tongsuo 持国家密码管理局商用密码检测中心产品认证证书，README 明确支持 TLCP/GB/T 38636-2020 与 SM2/SM3/SM4/ZUC，业界用户含支付宝、OceanBase、APISIX，2026 年恢复活跃发版（8.5.0-pre2）。据此：

- **合规主路径 = jt-crypto-api 的 tongsuo-backend**：密评范围内的密码运算（TLCP 握手、SM2 签名锚点、对象加解密）经 Tongsuo 承担，借用其产品认证与生态背书；
- RustCrypto 官方 sm2/sm3/sm4 crate 活跃，但 sm4 标注 hazmat（仅原语，GCM 等高层构造需自行组装）、sm4-gcm crate 已停滞：**pure-rust-backend 定位为测试、开发与未来认证储备**，不承担密评承诺；
- RK 保管与 DRBG 仍优先由已认证 TCM/密码卡/HSM 承担；
- 自研纯软件模块的产品认证周期与"应用层密码使用"解释口径仍是待验证问题（§7），但已不阻塞主路径。

## 4. 随机数设计

### 4.1 来源优先级

```text
1. TCM/TPCM 内置 DRBG（物理噪声源）        —— 首选
2. 密码卡 / HSM 的 DRBG                    —— 有硬件密码卡时
3. OS 内核 CSPRNG（getrandom()）           —— 受控回退
```

回退规则：使用第 3 级来源时，组件标记 `rng_source=software` 并进入**降级状态**——持续告警、写审计事件、KMS 拒绝在该状态下签发新 DEK（fail-closed）。单机开发嵌入模式可豁免（模式标记 `mode=embedded-development`）。

### 4.2 健康检测

- 上电自检：DRBG 已知答案测试（KAT）；
- 运行中：连续性测试（重复计数）与自适应比例测试，参照 NIST SP 800-90B 健康检测要求与 GB/T 32915-2016、GM/T 0005 随机性检测规范执行（编号专项核对）；
- 检测失败 → 该 DRBG 实例停止供数 → 组件进入 fail-closed（与 ADR-013 失效矩阵一致）。

### 4.3 软件 DRBG（回退实现要求）

- 基于 SM4 的 CTR_DRBG 结构；
- 种子必须来自硬件源或 OS CSPRNG，禁止时间/进程号等弱熵源；
- 每进程独立实例，重播种周期与实例生命周期在实现时固化；
- 供数接口与硬件 DRBG 统一（jt-crypto-api `jt_random_bytes`），上层无感。

### 4.4 nonce 域划分

呼应实现方案 §4.3 与 ADR-013：

```text
nonce 域 = (cluster_id, timeline_id, key_epoch, object_type, object_id)
```

- 不同域的计数器/随机空间完全隔离，禁止跨域复用；
- 随机 96-bit（GCM 标准用法）与计数器方案的取舍，在密码专项评审中基于对象写入速率做碰撞概率分析后冻结；
- compaction 生成新对象必须分配新 nonce（新 object_id 保证域隔离）。

### 4.5 算法使用清单（台账基础）

| 场景 | 算法/模式 | 位置 |
|---|---|---|
| 传输协议 | TLCP（SM2 双证书 / SM4-CBC / HMAC-SM3 / SM4-GCM） | jt-gateway、平面间通信 |
| 对象加密 | SM4 AEAD（模式按 GB/T 36624 核对后冻结） | jt-pageserver / jt-safekeeper |
| 口令存储 | SM3 + 盐 + KDF（KDF 结构专项冻结） | jt-identity、Compute |
| 签名/锚点 | SM2 签名（对象签名、审计 checkpoint、TSA） | jt-kms / jt-audit-* |
| 摘要/完整性 | SM3 | 全组件 |
| 密钥派生 | SM3/SM4 基 KDF（结构专项冻结） | jt-kms |

该清单是密评材料"算法台账"的直接数据源，实现变更必须同步更新。

## 5. 密评证据链自动化

对接规划文档功能线 P0"一键等保/密评证据包"：

```text
jtdb compliance report --framework gb39786 --level 3
```

- 自动采集：算法台账、密码产品清单、密钥全生命周期记录（KMS 日志 → 审计平面）、attest 度量记录、TLCP 配置基线；
- 输出：四性逐条自查表 + 证据附件索引 + 缺口清单；
- 人工补充材料（制度文档、人员记录）在报告中留出占位章节。

## 6. 接口与依赖

| 依赖方 | 关系 |
|---|---|
| jt-kms | RK 保管、DRBG 调度、密钥零化的合规载体 |
| jt-attest | 硬件密码资源探测、度量进证明链 |
| jt-crypto-api | 唯一密码原语入口；后端一致性测试集（§7） |
| JtEncryptedObject | nonce 域与 AEAD 参数的冻结前置（实现方案 §4.2/4.3） |
| jt-gateway | TLCP 配置基线与握手审计 |

## 7. 待验证问题

1. SM4-GCM 在密评语境下的适用性与模式核对（GB/T 36624）；
2. 自研纯 Rust 密码实现的商用密码产品认证路径与周期；过渡期合规模式（§3.3）的解释口径能否被测评机构接受；
3. TLCP 双后端（Tongsuo / 纯 Rust）一致性测试集与互操作矩阵；
4. "数据库内置密码功能"在密评中的产品边界解释（自用密码模块 vs 密码产品）；
5. 密评三级要求下的密钥管理流程文档深度（与 GM/T 0028 二级材料的合并复用）。
